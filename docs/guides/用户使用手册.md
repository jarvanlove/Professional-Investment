# 四只基金规则化交易系统使用手册

## 1. 系统简介

本系统是按照《四只基金规则化交易与动态仓位管理方案》（见 `docs/product/四只基金规则化交易与动态仓位管理方案_2026-08-05.pdf`）实现的本地执行平台，帮助你：

- 每周自动抓取四只基金的净值；
- 根据趋势评分、四道闸门和 B-S 理由代码生成交易信号；
- 记录交易日志，跟踪持仓和赎回费用窗口；
- 可选：使用 AI 把信号翻译成通俗中文解读。

**核心原则**：所有交易规则由 `packages/quant-core` 纯函数计算，LLM（AI 解读）只解释信号报告，不参与任何计算，也不保存历史。

## 2. 首次使用

### 2.1 安装与启动

前置：Python ≥3.11 + [uv](https://docs.astral.sh/uv/)、Node ≥20 + pnpm。

在**项目根目录**执行：

```bash
pnpm install        # 安装根依赖，同时安装 apps/web 依赖
```

然后启动后端：

```bash
cd services/quant-api
uv run uvicorn app.main:app --host 127.0.0.1 --port 8010 --reload
```

再启动前端（新终端）：

```bash
cd apps/web
pnpm dev
```

或者直接在项目根目录一键启动前后端：

```bash
pnpm dev
```

打开浏览器：http://localhost:3010

### 2.2 录入初始资金与持仓

1. 进入 **交易日志**（`/trades`）。
2. 录入第一笔 `入金`：日期选今天，方向选"入金"，金额填写你的真实本金（例如 **4000**）。
3. 依次录入四只基金的初始 `买入`：
   - 基金：001480 / 025343 / 027521 / 005052
   - 份额和确认净值以你在销售平台（支付宝、天天基金等）的实际成交为准。
   - 理由代码可选 B1（趋势建仓）或留空。
4. 进入 **持仓与资金**（`/portfolio`）查看总资产是否与你实际账户一致。

> **关于 19044.07**：如果你发现系统显示总资产是 19044.07，那是之前 README 里的示例金额（约 4000 本金 + 15000 追加的虚构场景）被录入到了本地数据库 `services/quant-api/data/investment.db`。这不是你的真实资金。请到"交易日志"删除或修改这笔 deposit，换成你的真实金额。

## 3. 每周信号操作流程

每周五（或你关注的净值披露日）重复以下步骤：

1. 打开 **每周信号**（`/signals`）。
2. 点 **"1. 更新净值"**：系统尝试通过 akshare 抓取四只基金净值（027521 使用 589210 代理净值）。
3. 点 **"2. 计算信号"**：系统生成当周信号，包括：
   - 市场模式（进攻 / 中性 / 利润保护 / 防守）
   - 每只基金的评分、目标权重、建议动作（买入 / 卖出 / 不动）
   - 理由代码（B1/B2/B3/B4/S1/S2/S3/S4/P1/P2/N0）
4. 根据信号，在下一开放日 15:00 前到你的场外销售平台手动下单。
5. 成交后回到 **交易日志** 补录实际交易（买入/卖出金额、份额、确认净值、费用）。

页面顶部的步骤条也提醒你完整流程：

> 更新净值 → 计算信号 → 按建议到场外平台下单 → 回来补录交易日志

## 4. AI 解读（可选）

### 4.1 配置 LLM

1. 进入 **设置**（`/settings`）。
2. 选择 **供应商**：
   - 支持 DeepSeek、Kimi、MiniMax、Qwen（通义）、GLM（智谱）。
   - 每家供应商提供通用版和 Coding 版两个入口，选择后会自动填充对应的 Base URL。
   - Coding 版通常需要单独的 API Key 或订阅套餐，请确认你手里的 Key 与所选入口匹配。
3. 填写 API Key：
   - 不同供应商的 Key 格式不同，请从对应官方平台获取。
   - 输入框支持点击眼睛图标显示/隐藏，点击复制图标一键复制。
4. Base URL 会随供应商自动填充，也可手动修改。
5. 模型选择：
   - 点击 **"获取模型列表"** 按钮，系统会根据已保存的 Base URL 和 API Key，实时从供应商拉取当前可用模型（加载时会有转圈）。
   - 如果刚修改了 Key 或 Base URL，请先点"保存"再获取。
6. 点"保存"。

你也可以不通过页面配置，直接把 Key 写入 `services/quant-api/.env`：

```bash
DEEPSEEK_API_KEY=sk-...
```

> 安全说明：Key 只保存在后端 SQLite 的 `app_settings` 表或本地 `.env` 文件中，**不会提交到 Git**。

### 4.2 使用 AI 解读

1. 在 **每周信号** 页面计算完信号后，点 **"AI 解读"**。
2. 系统会把当周信号报告发送给 LLM，返回三段中文解读：
   - 【本周结论】
   - 【逐只基金解释】
   - 【风险提示】
3. AI 只解释报告里已有的内容，不会给出报告之外的买卖建议。

## 5. 常见问题

### Q1: 净值抓取失败怎么办？

- 打开天天基金 App，手动查看对应基金净值。
- 使用 `POST /api/nav/import` 接口导入，或让 agent 帮你代为录入。
- 027521（广发）使用 589210 代理净值，需要累计 ≥61 个净值点；在此之前信号计算会返回 422 "数据不足"，属于正常设计。

### Q2: 为什么有时没有信号？

- 没有信号（N0）是正常结果，说明当周不满足任何买入/卖出条件，系统建议持有现金。
- 检查一下是否已更新净值、是否已计算信号。

### Q3: 系统显示的金额不对？

- 检查 **交易日志** 里的 deposit 金额是否为你的真实入金。
- 如果看到 19044.07，那是示例金额，请删除或修改。
- 确认初始买入的份额和净值与销售平台一致。

### Q4: 模型下拉框没有我想要的模型？

- 当前默认提供 DeepSeek 最新 V4 系列（`deepseek-v4-pro`、`deepseek-v4-flash`）。
- 旧的 `deepseek-chat` 和 `deepseek-reasoner` 已弃用，不再列出。

### Q5: 可以同时启动前后端吗？

- 可以，在项目根目录执行 `pnpm dev` 即可同时启动 quant-api(:8010) 与 web(:3010)。

## 6. 文件与数据说明

- `packages/quant-core`：纯算法库，禁止 Web/DB 依赖。
- `services/quant-api`：FastAPI + SQLite，数据保存在 `services/quant-api/data/investment.db`（不入 Git）。
- `apps/web`：Next.js 16 前端仪表盘。
- 测试：`pnpm test` 会运行 quant-core（53 例）、quant-api（18 例）、web（3 例）全部测试。
